# Technical Notes

- Use hexagonal architecture at all times. Keep business logic isolated from CLI, filesystem, network, storage, and other external adapters.
- Prefer functional testing before calling any feature complete. Unit tests are useful, but they do not prove the tool works the way the design intends.
- Take an agile approach to development. Avoid waterfall: underspecify when useful, prototype early, learn from the result, and refine from working behavior.
- `docs/docs/explanation/design.md` is the authoritative design; update it in the same PR when implementation forces an unrecorded decision. The phased implementation plan is `.journal/001/PLAN.md`.
- Release Please auth: repo variable `IMGOCI_RELEASE_APP_ID` + secret `IMGOCI_RELEASE_APP_PRIVATE_KEY`, sourced from 1Password item `imgoci-release-please` (Development vault, `op` CLI; app_id field + key.pem file). Confirm the app is installed on the repo before the first release.
- Repository settings are code: `.github/repository-settings.toml`, applied with `uv run .github/scripts/configure_github_repo.py apply --repo imgoci/go-oci-blob` (applied 2026-08-10; a few toggles are GitHub-UI-only, see `[unsupported]`).
- Hosted registries (ECR, Docker Hub, GHCR) ship broken chunked blob upload/resume because mainstream clients never use it; never make a spec'd-but-unexercised registry feature a default path without testing against real registries.
- E2E tests are build-tagged `e2e` (skip in plain `go test`; run via `go test -tags e2e` or the `root:test-e2e` moon task, which `root:check` includes so CI covers them). Put new e2e tests in e2e-tagged files.
- `moon run` breaks locally on machines with a legacy `~/.proto` store: moon v2 prepends `~/.proto/{tools/proto,shims,bin}` to task PATH, shadowing mise pins (go 1.26.5 vs pinned 1.26.4 → "compile: version mismatch"). CI is unaffected (no proto store on runners). Workaround: run the task's command directly via `mise exec --`. Real fix is a template-go-level decision (clean the proto store vs `.prototools` mirror pins vs `mise exec` wrappers in moon.yml).
- golangci-lint's shared cache replays stale findings for deleted worktree paths (generated-file filter fails open when the file is gone). Run `golangci-lint cache clean` after removing a worktree.
- Scripted-transport tests: `newTestContext` defaults to a zero RetryPolicy so conversations stay single-shot; retry behavior tests opt into a fast policy. Unexpected mockery calls in worker goroutines Goexit without filling result futures — script prospective concurrent requests with `.Maybe()` in failure-path tests.
- Registry credentials are origin-scoped: only marked same-origin requests use the caller's registry transport. Off-origin upload/storage Locations use `WithStorageTransport` (or the unauthenticated default), strip authorization, cookies, and Referer, and reject non-HTTP(S) redirects.
- Pull, resume, probe, fallback, and parallel-chunk requests share one lifetime `RetryPolicy.MaxAttempts` budget. Every 206 response must carry a valid `Content-Range` matching the requested interval before bytes are exposed.
- Upload request bodies use a streaming pipe because `http.RoundTripper` may consume or close `Request.Body` asynchronously after returning. Preserve that ownership handoff, exact-size validation, and replay synchronization when changing Push or chunked upload code.
